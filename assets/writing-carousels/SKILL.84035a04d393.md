# Carousel Story Writer

## Goal

Turn the author's real material into a carousel that earns each swipe, keeps the author's voice, uses evidence honestly, and fulfills the promise of the first slide.

A carousel is not a long post cut into pictures. Each slide must either change the reader's state or deliver separate value.

## Core workflow

1. Intake snapshot
2. Constraints ledger
3. Format fit
4. Source priority and grounding
5. Product status discipline
6. Research gate
7. Concept
8. Archetype
9. Promise contract
10. Spine before copy
11. Copy
12. Visual handoff
13. QA
14. Output mode
15. Approval Lock and Edit Delta
16. Learning loop

## Intake snapshot

Extract what is already known: source material, author, audience if known, publication goal, desired action, product or offer, facts and proof assets, voice requirements, and tool constraints.

Do not ask again for information already present.

## Constraints ledger

Treat explicit constraints as persistent until changed:
- banned words or phrases
- punctuation preferences
- profanity allowed or forbidden
- list preference
- length
- actual slide limit of the target tool
- CTA
- approved phrases or slides that must remain unchanged

## Format fit

Check whether multiple screens add meaning. If another format is better, say so.

If the user still wants a carousel, use the minimum number of slides that honestly carries the idea. Never add filler just to reach a slide count.

## Grounding

Priority:
1. current explicit request
2. user-supplied facts, files, quotes, links, approved wording
3. author voice samples
4. verified external sources when needed
5. working heuristics

Do not invent audience pain, numbers, results, testimonials, product features, origin stories, or quotations.

## Product status discipline

Separate:
- works now
- planned
- idea
- unknown

Never present a planned feature as already available.

## Research gate

Research is required for external facts, numbers, news, research claims, market comparisons, current platform claims, or generalizations wider than the author's own experience.

It is usually not required for a personal story, a real first-party case, an author's opinion without external factual claims, or transformation of user-supplied text.

When research is used:
- connect each factual claim to a source that supports it
- do not make wording stronger than the evidence
- separate facts from inference
- say when evidence is insufficient

## Concept

A concept should answer:
- what tension or recognition opens the post
- why the reader keeps swiping
- where the turn happens
- what the reader gets at the payoff

If several materially different directions are strong, offer 2 to 4 and recommend one.

## Archetype

Choose what fits: Story, How-to, Framework, List, Myth-bust, Before/after, Product proof, Transformation, Hybrid.

Do not force one template on every topic.

## Promise contract

Define:
- Hook
- Promise
- Payoff
- Proof
- CTA

If the cover promises N items, the body must visibly deliver N items.

## Spine before copy

For each slide define:
- slide job
- what the reader now understands
- what changed
- what tension remains
- why the next swipe is needed
- what proof or example belongs here

Rules:
- S1 stops and sets an honest expectation
- S2 and S3 are not empty setup
- every slide moves the story or gives value
- merge adjacent slides with the same job
- no transition slide whose only job is "more next"
- chronology alone is not dramaturgy
- one slide, one main job

## Copy

Text levels:
- Headline
- Body
- Accent / Kicker
- List items

Rules:
- headline works without body
- body supports instead of hiding the point
- lists when they scan faster
- no essay-sized slide
- no pseudo-wisdom
- preserve causal logic
- real author phrasing beats polished generic copy

Voice priority:
1. explicit style requirements
2. real author samples
3. current raw material
4. neutral natural language fallback

## Visual handoff

For each slide define only what is useful:
- visual job
- real asset
- relation to the text
- focal point
- slide type

Proof asset priority:
1. real screenshot or interface
2. real message, testimonial, or document
3. real process photo
4. generated mockup only after real proof is unavailable or unnecessary

Never replace evidence with invented UI.

## QA

Check:
- Promise Closure
- Headline-only
- Early-slide gate
- Swipe logic
- One-slide-one-job
- Proof comprehension
- Voice
- Constraints
- Mobile readability
- CTA coherence

If a hard gate fails, return to the relevant stage.

## Output modes

Working mode:
Audience / Job, Concept, Hook / Promise / Payoff / Proof / CTA, Spine, QA notes.

Copy-ready:
final text only, one block per slide, no analysis between blocks, lists remain lists.

Studio handoff:
slide_id, headline, body, accent, list_items, asset_needed, visual_job, layout_note, style_reference.

Audit mode:
identify the structural issue, explain why it matters, propose the smallest fix.

## Approval Lock and Edit Delta

Approved wording, slides, structures, and blocks are source of truth until the user directly requests a change.

For a point edit, change only the requested delta and lock everything else.

## Learning loop

Use publication data and qualitative feedback as observations, not automatic laws.

Evidence levels:
- Research-backed
- Current design/platform guidance
- Benchmark/observational
- Practitioner heuristic
- Case-based rule

## Definition of done

The carousel is ready when the format is justified, facts are grounded, the concept is clear, the promise is honest, the spine has no filler, the author's voice is preserved, proof supports the claim, the ending fulfills the promise, the CTA matches the goal, and the output is delivered in the requested mode.
